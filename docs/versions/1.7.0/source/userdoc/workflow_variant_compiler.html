Variant Compiler Guide

A comprehensive reference for the graphical interface of the Variant Compiler tool.

Installation

  1. Navigate to the workflow_tools folder.

  2. Run install.bat on Windows or install on macOS.

  3. Wait for the installation to complete. This may take a few minutes while a Python virtual environment is created and dependencies are installed.

  4. Once the installation is complete, the GUI launchers and CLI .bat files are available in the workflow_tools folder.

Starting the UI

Double-click the .bat file in the workflow tools folder, run variant-compiler-ui from the command line, or run main.py with Python (SSCA required).

The application is organized into four panels + a Log panel:

The menu bar spans the top. The scene filename is shown in the center of the menu bar, and the workspace path (with * when unsaved) appears on the right.

Preview Menu

Opens the loaded scene in an external USD viewer for quick inspection.

Scene Hierarchy Panel

Displays the prim tree of the imported USD scene.

Loading a Scene

Click Import Scene in the panel header, or use Import → Import Scene… from the menu. A progress dialog appears while the scene loads. The title bar updates to show the filename.

Navigating the Tree

  • The tree expands one level by default when a scene is loaded.

  • Click any row to select a prim and show its properties in the Prim Details sub-panel below.

  • Drag a prim row onto the Prim Path field inside Variant Set Details to assign that prim’s path to a variant set.

  • Double-click a prim to select it.

Searching and Filtering

  • Type in the Search prims… field to filter the tree by prim name. The tree expands matching branches automatically.

  • Enable Match All Keywords to require every space-separated term to match (AND). By default any term is sufficient (OR).

  • Press Enter or click away to apply the search immediately; otherwise it applies after a short pause.

  • Click the type tag buttons (Mesh, Material, Xform, Scope, Camera, Light) to show only prims of that type. Multiple tags can be active at once.

  • The search field shows a clear button (×) when a type filter is active, so everything can be reset in one click.

Prim Details Sub-panel

Shows the selected prim’s properties (name, type, path, and attributes). Click the ▲/▼ button in the Prim Details header to collapse or expand the sub-panel.

Prim Indicators

Prims that are assigned to one or more variant sets display a blue dot on their row in the tree.

Variant Sets Panel

Lists every variant set in the current workspace.

Creating a Variant Set

Click + New Variant Set in the panel header. A new entry appears in the list and is selected automatically, with the name field focused and ready to type.

Variant Set List Items

Each card shows:

  • Lock / Unlock icon — A padlock icon indicates whether the set is read-only (loaded from the scene) or editable (newly created). Hover for a tooltip.

  • Name — The variant set name, optionally followed by -> selected_variant when a default variant is active.

  • Prim path — The USD prim this set is attached to.

  • Types and count — The opinion types used across variants (e.g. ATTRIBUTE - 4 variants).

  • Child variant sets — When nested variant sets exist, a count label and expand/collapse button appear.

  • Error / Warning icons — Validation problems are shown as alert icons with tooltip details.

  • Duplicate button — Copies the variant set (and all its variants and opinions) to a new editable set.

  • Delete button — Removes the set after a confirmation prompt. Only shown for editable sets.

User-created (editable) sets are listed before read-only (existing) sets. Within each group, sets are sorted alphabetically by name then by prim path.

Searching and Filtering

  • Type in Search sets… to filter by name, prim path, variant names, opinion types, target prims, referenced files, or attribute values.

  • Enable Match All Keywords (AND logic) or leave unchecked for OR logic (default).

  • Click New to show only user-created sets.

  • Click opinion type tags (Attribute, Controller, Geometry, Material, etc.) to filter by type. When multiple tags are selected, all must be present.

  • The search field shows a clear button when any filter is active.

Nested Variant Sets (Child Sets)

Variant sets can contain child sets owned by specific variants. Click the expand/collapse button on a parent card to show or hide its children inline in the list, indented by nesting level. Search auto-expands parents when a matching child exists.

Variant Set Details Panel

Shows the full configuration of the selected variant set. Click any variant set in the center panel to load it here.

Variants List

Each variant in the set is shown as a collapsible card.

Adding Variants

  • Click New Variant in the Variants section header to add a blank variant. The name field is focused for immediate renaming.

  • Click Import (folder icon) to bulk-import variants from a directory of asset files (see Bulk Import below).

Variant Card (Editable Sets)

  • Checkbox — Marks this variant as the default selected variant. Only one variant can be selected at a time.

  • Name field — The variant identifier. Must be a valid USD identifier.

  • Expand/Collapse arrow — Toggles the opinions list for this variant.

  • Duplicate button — Copies the variant and all its opinions.

  • Delete button — Removes the variant.

  • Drag handle — Drag variants to reorder them within the set.

Variant Card (Read-only Sets)

Name is shown as a label only. No editing controls are visible.

Bulk Import

Bulk import allows you to create multiple variants at once by selecting a folder of asset files. Each file generates a new variant with opinions based on the chosen opinion type.

Click the Import (folder icon) button in the Variants section header to open the bulk import panel. The variants list is replaced with an import form:


  1. Set the Target Prim — the prim path all opinions will point to.

  2. Choose Opinion Type — MATERIAL or GEOMETRY.

  3. Click Add Files to pick individual files, or Add Directory to scan a folder. Files can also be dragged directly onto the list.

  4. Remove individual files with the x button.

  5. Click Import to create one variant per file, using the filename (without extension) as the variant identifier.

  6. Click Cancel to return to the variants list without importing.

Typical Workflow

1. Start the UI

Double-click on the .bat file in the workflow tools folder, run variant-compiler-ui from the command line, or run main.py with Python (SSCA required).

2. Create or Open a Workspace

  • File → New Workspace to start from scratch.

  • File → Open Workspace… (Ctrl+O) to reload an existing .vws file.

3. Import a Scene

Click Import Scene in the Scene Hierarchy panel header and select a USD/USDZ/USDA/FBX file. The prim tree populates and the filename appears in the menu bar.

4. Create a Variant Set

Click + New Variant Set in the Variant Sets panel. Name it (e.g. BodyColor) and set the Prim Path — type it or drag a prim row from the Scene Hierarchy.

5. Add Variants

In the Variant Set Details panel, click New Variant for each option (e.g. red, blue, silver). Rename each variant as prompted.

6. Add Opinions to Each Variant

Expand a variant card, click + Add Opinion, choose the opinion type, and fill in the required fields. For example, a MATERIAL opinion needs a Target Prim and either a Referenced File or Referenced Prim.

A single variant can have multiple opinions. Common combinations:

  • GEOMETRY + MATERIAL — Swap geometry and assign matching material.

  • CONTROLLER — Chain to another variant set (e.g. selecting large_wheels also selects the matching WheelMaterial variant).

7. Set a Default Selection

Check the checkbox next to the variant that should be active by default when the USD file is opened.

8. Save the Workspace

Ctrl+S saves to a .vws file. The title bar clears the * unsaved indicator. Workspaces can be reopened via File → Open Recent.

9. Export the Scene

Export → Export Scene… validates all variant sets, then writes a USD file with the compiled variant data. If validation errors exist they are logged as clickable links and the export is blocked until corrected.

Tips

  • Drag prim paths — Any prim path field in Variant Set Details accepts drag-and-drop from the Scene Hierarchy prim tree.

  • Duplicate to iterate — Use the duplicate button on a variant set or variant to copy a working configuration before making changes.

  • Lock icon = read-only — Variant sets loaded from the scene are locked (read-only). Duplicate them to create an editable copy.

  • Search is deep — The Variant Sets search scans names, prim paths, variant identifiers, referenced files, and attribute values, so you can search for a filename or material path to find which set uses it.

  • Validation links — Clicking a red error in the Logs panel jumps directly to the broken field, saving time hunting for the problem.

  • `.vws` vs `.json` — A workspace (.vws) saves the full UI state including the scene reference. A variant config (.json) is portable and works with the CLI. Use Export → Export Variant Config to generate a CLI-compatible config from the UI.

CLI

The variant-compiler command-line tool runs the same compilation pipeline as the UI, without a graphical interface. Use it for headless batch builds, CI pipelines, or scripted automation.

This CLI uses JSON files exported from the UI with Export → Export Variant Config…, or created manually from the schema described below.

After installation, the CLI entrypoint is abailable in the workflow_tools folder as Substance3DVariantCompilerCLI.bat on Windows or variant-compiler on macOS. You can also run variant_compiler/CLI/main.py with Python directly (SSCA required).

Quick Examples

Build from a config alone (no input scene):

variant-compiler -c config.json -o output.usd

Add variants to an existing USD scene:

variant-compiler -c config.json -i base_scene.usd -o output.usd

Export as USDZ with verbose logging:

variant-compiler -c config.json -i scene.usd -o output.usdz -vv

Resolve assets relative to a custom directory:

variant-compiler -c config.json -i scene.usd -o output.usd -w ./assets

{
  "target_prim": "/root/room/wall",

{

Path Resolution

Relative paths in referenced_file are resolved in this order:

  1. Absolute path — used as-is if the path exists on disk.

  2. Relative to the input scene — if --input is provided, resolves from that file’s directory.

  3. Relative to --working-directory — if provided, resolves from that directory.

  4. Project-relative — paths starting with / that do not resolve as absolute are treated as project-relative and resolved against the working directory.

  5. Current working directory — fallback when neither --input nor --working-directory is supplied.

Path example

Resolved as

"materials/wood.sbsar"

Relative to scene dir (or working dir / CWD as fallback)

"/materials/wood.sbsar"

Project-relative, resolved against working directory

"C:/Projects/assets/wood.sbsar"

Absolute (Windows)

"/home/user/assets/wood.sbsar"

Absolute (Linux / macOS)

Relationship to the UI

The CLI and the UI share the same underlying config format.

  • Author in the UI, run in CI — Use the UI to build and validate a config, then export it via Export → Export Variant Config (.json). Pass that file directly to the CLI for headless batch builds.

  • Author in JSON, inspect in the UI — Write a config by hand or generate it programmatically, then import it into the UI via Import → Import Variant Config (.json) to visualize and edit it.

The .vws workspace format used by the UI is a superset of the JSON config and also stores the associated scene path. The exported .json is the portable, CLI-compatible subset.
